# Cashbook V0.1 Plan

## Definition of done

V0.1 is complete when:

1. Two separate users can sign in to the self-hosted instance.
2. One user creates a shared ledger and invites the other.
3. Both Android devices see the same ledger.
4. WeChat/Alipay payment notifications are filtered locally.
5. A recognized notification produces a CandidateTransaction without persisting raw text.
6. Duplicate payment signals do not create duplicate transactions.
7. High-confidence candidates can be accepted into the shared ledger.
8. The second phone receives the synchronized transaction.
9. No SMS, AccessibilityService or background screen capture permission is required.

## Work packages

### P0 — Foundation

- [x] Repository initialized.
- [x] Privacy architecture defined.
- [x] 2C/2G server deployment skeleton added.
- [ ] Pin upstream BeeCount and BeeCount Cloud revisions.
- [ ] Establish upstream update procedure.

### P1 — Cloud bring-up

- [ ] Start BeeCount Cloud on VPS.
- [ ] Disable public registration.
- [ ] Configure HTTPS or private overlay networking.
- [ ] Create two users.
- [ ] Validate shared-ledger invite and realtime sync.
- [ ] Verify backup + restore procedure.

### P2 — Android privacy gate

- [ ] Notification listener integrated.
- [ ] Immediate package allowlist filtering.
- [ ] Release build raw-content logging prohibited.
- [ ] Raw notification text never written to local DB.
- [ ] Feature can be disabled independently.

### P3 — Payment parser

Initial sources:

- [ ] WeChat
- [ ] Alipay

Later, only if needed:

- [ ] selected bank apps

Output schema:

```
CandidateTransaction
- source
- amount
- direction
- merchant
- occurredAt
- confidence
- fingerprint
```

### P4 — Dedup and confirmation

- [ ] Same notification repeated by Android is deduplicated.
- [ ] Same transaction observed through multiple channels is deduplicated.
- [ ] High-confidence threshold configurable.
- [ ] Low-confidence candidates appear in confirmation UI.

### P5 — Shared ledger integration

- [ ] Candidate knows the local user/payer.
- [ ] Confirmed transaction targets selected shared ledger.
- [ ] Creator identity survives cloud sync.
- [ ] Other member receives realtime update.

## Explicitly out of V0.1

- READ_SMS / RECEIVE_SMS
- AccessibilityService parsing
- automatic MediaProjection capture
- cloud LLM parsing of raw notification text
- purchase approval / wish-list workflow
- monthly AI summary
